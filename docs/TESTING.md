# Windows 与 Chrome 手工验收

当前交付未完成 Windows + 真实代理客户端的端到端验证。本环境 Chromium 151 的管理员策略禁止加载已解压扩展；`npm run smoke` 在等待扩展 service worker 阶段失败，故未验证真实扩展 API 和网络行为。该脚本使用临时本地 HTTP 代理，供允许加载扩展的 Linux 环境复现，不可用它代替 Windows 客户端验收。下面是待执行验收清单，不能用单元测试通过代替。

## 每种入口重复执行

在 Windows 10/11 的普通 Chrome 配置文件中，关闭系统代理，记录 Chrome、OS、客户端版本和配置协议。分别用 v2rayN、Clash Verge/Mihomo、sing-box、Shadowsocks 客户端**实际暴露的标准 HTTP/SOCKS 入口**测试；不是每个客户端都支持全部入口协议。不要依据示例猜端口，从客户端配置读取。HTTPS 是连接到代理入口的 TLS，不是目标网站 HTTPS，也不是节点协议。

1. 启动客户端，仅开启本地代理监听，保持 Windows 系统代理关闭；确认系统设置没有变动。
2. 加载 dist，确认向导打开；添加代理 A 和 B，可选远端 SOCKS5，端口可用非标准值。
3. 全局代理：打开外部出口 IP 网站，对照客户端日志；验证与系统直连出口的差异。HTTPS/SOCKS5 分别验证。
4. 全局直连：确认客户端没有相应新请求。关闭旧连接/重新打开页面，排除 keep-alive 影响。
5. 智能：分别配置 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、MATCH、出口 B、DIRECT；检查第一条匹配、域名边界、排序行为。
6. REJECT：域名拒绝应在主框架与子资源显示 ERR_BLOCKED_BY_CLIENT，较早 DIRECT 规则应允许；在 global/direct 模式拒绝规则应清除。
7. 仅使用 IPv4 字面 URL 测试 CIDR；不得把域名的 DNS 地址当作 CIDR 匹配结果。
8. 停止代理，重新发起原本走代理的请求，应失败且不静默改用直连；检查客户端、抓包和目标日志。测试固定代理与 PAC；不能只看 Popup。
9. 输入非法地址/端口、缺失出口、超限文件、未知策略组，应拒绝更改并保留旧配置。
10. 添加、编辑、删除、切换当前与默认入口，代理被规则引用时禁止删除；重启 Chrome、重载扩展后配置保留。
11. 安装另一代理扩展或企业策略制造权限冲突，检查控制状态、失败消息与旧配置保留。多 Options 窗口同时保存测试版本冲突。
12. 诊断：授权单目标站点，检查直连/代理路由、HTTP 错误、超时、拒绝、权限未授予、重定向失败。无法明确区分 fetch 底层原因应显示限制。
13. 深色、浅色、跟随系统、窄屏设置、键盘焦点、减少动画设置与 Popup 布局。
14. 检查禁用/卸载后 Chrome 释放代理控制；测试无痕独立配置和其他扩展干扰时，不承诺 ProxyFlow 接管。

## 网络安全边界测试

对比 DNS 请求、WebRTC STUN、QUIC/HTTP3、回环地址、Chrome 内部服务与既有连接。PAC 对回环/浏览器特殊请求的绕过行为需实测，不能仅靠返回代理指令判断。V0.3 可选择限制 WebRTC 非代理 UDP，但实际效果需逐项验证，不能据此宣称防止全部 IP 泄漏。TLS 代理证书必须可信，本版不绕过证书验证。认证代理不支持，遇到挑战可能显示 Chrome 提示或失败。

记录每次测试的配置模式、规则、客户端版本、时间、实际请求、预期/实际出口与失败表现。共享日志前删除服务器地址、敏感 URL、凭据与个人信息。

## V0.2 导入验收（待真实扩展执行）

1. 使用 examples/ 下的三个格式，先预览，映射 HomeGroup 或 proxy 至已创建的入口，再预览应用；确认规则顺序与运行模式不变。
2. 预览后修改源文本、格式、映射、附件；旧预览应失效。另一 Options 窗口修改浏览器配置后应要求重新解析。
3. 添加 Clash inline/domain/classical 提供者、http/file 本地附件及 Shadowrocket RULE-SET 附件，检查展开位置、标签匹配和没有远程网络请求。
4. 加入 GEOIP、Xray AND、regexp、IPv6、缺失附件和未映射出口，报告须明确列出；默认不可应用，部分导入须确认。非法域名、缺失代理、重复 JSON outbound 标签、YAML 重复键、别名与超限文件始终禁止应用。
5. 检查 IP 字面值与 DNS 策略区别，IPIfNonMatch/IPOnDemand 的 IP 规则不得被错误转换；REJECT+CIDR 组合不得应用。
6. 检查完整配置中的节点、密码、远程 URL 参数不出现在导出报告或调试日志；报告中的规则域名与出口标签属于预期用户数据。
7. 从 V0.1 在原目录更新 dist 后点击扩展重新加载，旧配置与模式应保留。存储 schema 仍为 version 1，仅应用版本升级到 0.2.0。

## V0.3 实机验收（全部待执行）

1. 从 V0.1/V0.2 原配置升级，检查新增 alarms 权限提示和重新启用行为；代理、规则、主题与 revision 保留，新订阅为空，广告和 WebRTC 限制默认关闭。schema 保持 version 1。
2. 使用自己可控制的有效证书 HTTPS 来源，检查保存手动订阅不下载，点击更新才请求主机授权；拒绝权限不访问。确认授权覆盖该主机全部端口/路径，并检查当前直连/代理出口。
3. 在来源日志检查无 Cookie/referrer、无重定向跟随；分别返回正常文本、HTTP 503、302、HTML、坏 UTF-8、超限 Content-Length 与无长度超限流。下载失败不变路由、不直连，旧候选保留。
4. 下载 Shadowrocket/Clash/Xray 常见规则并显式映射出口；确认节点未执行、外部 rule-providers 未下载、错误和跳过项明确显示；确认后才替换全部规则。多订阅不自动合并，预览期间修改配置/源参数后旧候选不能应用。
5. 开启 6/24 小时周期，观察 alarm 下载与休眠/重启后的延迟。来源超过 3 个到期时验证每轮上限；撤销来源权限后失败，不弹窗、不改变活动规则。删除来源应清理状态；关闭全部自动周期后应无调度。
6. 开启广告域名列表，以自有测试域名和子域验证主页面、图片/脚本被 DNR 拦截，相似但无后缀边界的域名不拦截；三种模式均生效，路由 DIRECT/allow 不豁免广告规则。关闭后恢复访问，不产生浏览日志或计数。
7. WebRTC 首次开启申请 privacy，拒绝不生效；授予后读取实际 disable_non_proxied_udp 与 regular 控制级别。对比 STUN/UDP 和视频通话，记录预期/实际 IP；关闭只清自己的覆盖。其他扩展或企业策略冲突应禁止启用，撤销 privacy 后展示状态差异并阻止把限制称为已生效。
8. 诊断测试权限冲突、额外代理 bypass、DNR 条件漂移、WebRTC 期望未生效、广告/REJECT、缺少站点权限、HTTP 状态、超时和代理错误事件。对无法区分的代理/目标/DNS/TLS 错误应诚实提示，不能把同期错误当作唯一原因。
9. 模拟 DNR、privacy、proxy、storage 写入与恢复失败，确认可观察错误、旧配置保留及重新保存修复；跨 API 无原子保证，记录短暂不一致与崩溃重启表现。
10. 检查更新缓存/日志不包含完整远程节点内容、密码或网络异常中敏感 URL。配置中的订阅 URL 令牌属于明确本地敏感内容，导出和截图前清理。

`scripts/smoke.mjs` 新增广告跨模式拦截与 AD_BLOCKED 诊断步骤，供获准加载解压扩展的 Linux Chromium 环境运行；WebRTC 授权、HTTPS 来源与真实调度仍按以上清单手动验收。脚本尚未在当前受限环境通过。
